## Использование

Собрать бинарный файл краулера:

```bash
make build
```

Запустить все автоматические проверки:

```bash
make test
```

Проанализировать сайт:

```bash
make run URL=https://example.com
```

Если `URL` не указан, команда выведет короткое сообщение и справку по использованию.

## JSON-отчет

Краулер возвращает отчет в формате JSON по [спецификации JSON](https://www.json.org/json-en.html).
Все ключи присутствуют всегда. Если ошибки нет, поле `error` содержит пустую строку.
Поля времени `generated_at` и `discovered_at` записываются в формате ISO8601/RFC3339.

Пример отчета:

```json
{
  "root_url": "https://example.com",
  "depth": 1,
  "generated_at": "2024-06-01T12:34:56Z",
  "pages": [
    {
      "url": "https://example.com",
      "depth": 0,
      "http_status": 200,
      "status": "ok",
      "error": "",
      "seo": {
        "has_title": true,
        "title": "Example title",
        "has_description": true,
        "description": "Example description",
        "has_h1": true
      },
      "broken_links": [
        {
          "url": "https://example.com/missing",
          "status_code": 404,
          "error": "Not Found"
        }
      ],
      "assets": [
        {
          "url": "https://example.com/static/logo.png",
          "type": "image",
          "status_code": 200,
          "size_bytes": 12345,
          "error": ""
        }
      ],
      "discovered_at": "2024-06-01T12:34:56Z"
    }
  ]
}
```

Поля верхнего уровня:

- `root_url` — стартовый URL, переданный в анализ.
- `depth` — запрошенная глубина обхода.
- `generated_at` — время формирования отчета.
- `pages` — страницы, которые попали в обход.

Поля страницы в `pages`:

- `url` — адрес страницы.
- `depth` — глубина страницы относительно `root_url`; стартовая страница имеет глубину `0`.
- `http_status` — HTTP-код ответа страницы; `0`, если ответа не было.
- `status` — `ok` для успешно обработанной страницы или `error` при ошибке.
- `error` — описание ошибки страницы или пустая строка.
- `seo` — базовые SEO-признаки: наличие и текст `<title>`, наличие и текст meta description, наличие `<h1>`.
- `broken_links` — ссылки со страницы, которые вернули ошибочный статус или не были запрошены.
- `assets` — найденные ресурсы страницы: изображения, скрипты и стили.
- `discovered_at` — время добавления страницы в отчет.

Поля элементов `broken_links`:

- `url` — адрес битой ссылки.
- `status_code` — HTTP-код ответа; `0`, если ответа не было.
- `error` — текст ошибки или HTTP-статуса.

Поля элементов `assets`:

- `url` — адрес ресурса.
- `type` — тип ресурса: `image`, `script` или `style`.
- `status_code` — HTTP-код ответа ресурса; `0`, если ответа не было.
- `size_bytes` — размер ресурса в байтах.
- `error` — описание ошибки ресурса или пустая строка.

Опция `IndentJSON` меняет только форматирование JSON: добавляет отступы и переносы строк, но не меняет содержание и порядок ключей.
CLI печатает JSON без дополнительного текста до или после отчета и добавляет один завершающий перевод строки.

## Глубина обхода

Используйте CLI-флаг `-depth`, чтобы изменить количество уровней обхода внутри исходного домена:

```bash
go run ./cmd/hexlet-go-crawler -depth 2 https://example.com
```

Стартовый URL всегда попадает в отчет с `pages[].depth = 0`. Его прямые внутренние ссылки получают `pages[].depth = 1`, ссылки с этих страниц получают `pages[].depth = 2` и так далее.

Значение `-depth` задает, сколько уровней включить в отчет. Например, `-depth 1` добавляет только стартовую страницу, а `-depth 2` добавляет стартовую страницу и ее прямые внутренние ссылки. Ссылки за пределами исходного домена не добавляются в `pages`, но могут проверяться и попадать в `broken_links`, если возвращают ошибочный статус или не могут быть запрошены.

## Скорость обхода

По умолчанию краулер не добавляет искусственную задержку между HTTP-запросами.

Чтобы ограничить скорость, используйте один из CLI-флагов:

```bash
go run ./cmd/hexlet-go-crawler --delay=200ms https://example.com
go run ./cmd/hexlet-go-crawler --rps=5 https://example.com
```

`--delay` принимает формат `time.Duration`: `200ms`, `1s`, `2m`, `1h`.
`--rps` задает целевое количество запросов в секунду для всего процесса. Если указаны оба флага, `--rps` имеет приоритет над `--delay`.

При использовании пакета напрямую за скорость отвечают поля `crawler.Options.Delay` и `crawler.Options.RPS`. Положительное значение `RPS` переопределяет `Delay`; положительное значение `Delay` задает минимальный интервал между соседними HTTP-запросами всего процесса.

## Повторные попытки

Используйте CLI-флаг `--retries`, чтобы задать максимальное число повторных попыток для одного URL:

```bash
go run ./cmd/hexlet-go-crawler --retries=2 https://example.com
```

`--retries=2` означает первый запрос и до двух повторов, то есть не больше трех обращений к одному URL. Отрицательные значения считаются как `0`.

Повторы выполняются только для временных проблем:

- сетевой сбой при выполнении запроса;
- HTTP `429 Too Many Requests`;
- HTTP `5xx`, например `500`, `502`, `503`, `504`.

HTTP `4xx`, кроме `429`, не повторяются. Отмена контекста или превышение таймаута сразу останавливают дополнительные попытки. Между попытками есть небольшая ненулевая пауза, чтобы не отправлять повторные запросы бурстом.

В отчете фиксируется результат последней попытки. Если последний ответ для ссылки был `404`, она попадет в `broken_links` со статусом `404`; если последняя попытка завершилась успешно, ссылка не считается битой.
